# ASR 延遲比較報告：gpt-realtime-whisper vs gpt-4o-transcribe (Batch)

**日期**：2026-05-27  
**版本**：v1.0  
**測試環境**：Node.js v22 / Ubuntu 22.04 / 新加坡 → api.openai.com  
**測試語言**：繁體中文（zh-TW），護理場景句子 10 句

---

## 1. 摘要

| 指標 | gpt-realtime-whisper | gpt-4o-transcribe (Batch) | 勝出 |
|---|---|---|---|
| **Final 延遲（平均）** | 1,684ms | ~1,099ms | 🏆 Batch |
| **首字延遲（Partial）** | **638ms** | N/A | 🏆 Realtime 獨有 |
| **CER（繁體中文）** | 9.1%（OpenCC 後） | **0.0%** | 🏆 Batch |
| **繁體中文保證** | ⚠️ 需 OpenCC 後處理 | ✅ prompt 直接控制 | 🏆 Batch |
| **成本/分鐘** | $0.017 | ~$0.006 | 🏆 Batch |
| **架構複雜度** | WebSocket 長連線 | 單次 HTTP POST | 🏆 Batch（更簡單） |
| **串流輸出** | ✅ 字元級 Delta | ❌ 無 | 🏆 Realtime 獨有 |

**核心結論**：在「等待最終結果」的場景下，Batch 模式延遲更低、準確度更高、成本更低。Realtime 的核心優勢是**串流首字延遲（638ms）**，適合需要即時字幕顯示的場景。

## 5. 優化潛力分析

### 5.1 gpt-realtime-whisper 可優化空間

| 優化方向 | 可消除延遲 | 方法 | 難度 |
|---|---|---|---|
| **預建 WebSocket 連線池** | ~940ms | 頁面載入時預建並保持連線 | 中 |
| **邊錄邊傳（VAD 串流）** | ~390ms（commit 確認） | 偵測到語音即開始串流，不等錄音結束 | 高 |
| **理論最低延遲** | **~1,217ms** | 預建連線 + 即時串流 | — |

### 5.2 gpt-4o-transcribe Batch 可優化空間

| 優化方向 | 可消除延遲 | 方法 | 難度 |
|---|---|---|---|
| **HTTP/2 連線複用** | ~60ms | Keep-Alive 複用 TLS 連線 | 低 |
| **gpt-4o-mini-transcribe** | ~200-300ms | 切換至更快的 mini 模型 | 低 |
| **理論最低延遲** | **~700-800ms** | mini 模型 + 連線複用 | — |

## 6. 使用場景建議

| 使用場景 | 推薦方案 | 原因 |
|---|---|---|
| **即時字幕顯示（使用者說話時同步顯示）** | gpt-realtime-whisper | 首字延遲 638ms，串流 Delta 輸出 |
| **最終轉錄 → 翻譯 → TTS 管線** | gpt-4o-transcribe Batch | 延遲更低（1,099ms vs 1,684ms），準確度更高 |
| **繁體中文醫療術語精確控制** | gpt-4o-transcribe Batch | prompt 直接控制，無需後處理 |
| **成本敏感場景** | gpt-4o-mini-transcribe | 最低成本，速度接近 |
| **混合架構（最佳體驗）** | Partial: Realtime + Final: Batch | 即時字幕 + 高品質最終轉錄 |

### 6.1 混合架構設計（推薦）

```
使用者說話
    │
    ├─→ [gpt-realtime-whisper WebSocket]
    │       └─→ transcript.delta → 即時字幕顯示（<100ms 首字）
    │
    └─→ [VAD 偵測靜音]
            └─→ [gpt-4o-transcribe Batch]
                    └─→ Final 轉錄 → 翻譯 → TTS（~1,099ms）
```

此架構結合兩者優勢：使用者看到即時字幕的同時，後台以更高品質的 Batch ASR 產出最終轉錄並翻譯。

## 7. 結論

**在「等待最終轉錄結果」的場景下**，`gpt-4o-transcribe Batch` 在延遲（1,099ms vs 1,684ms）、準確度（CER 0.0% vs 9.1%）、繁體中文控制、成本各方面均優於 `gpt-realtime-whisper`。

**gpt-realtime-whisper 的不可取代優勢**在於串流輸出（首字延遲 638ms），這是 Batch 模式結構上無法實現的。對於護理翻譯系統，建議採用**混合架構**：以 Realtime 提供即時字幕體驗，以 Batch 提供高品質最終轉錄。

| 決策維度 | gpt-realtime-whisper | gpt-4o-transcribe Batch |
|---|---|---|
| Final 延遲 | 1,684ms | **1,099ms** ✅ |
| 首字延遲 | **638ms** ✅ | N/A |
| 準確度 CER | 9.1% | **0.0%** ✅ |
| 繁體中文 | 需 OpenCC | **prompt 直接控制** ✅ |
| 成本 | $0.017/min | **$0.006-0.012/min** ✅ |
| 串流輸出 | **✅** | ❌ |
| 架構複雜度 | 高（WebSocket 長連線） | **低（HTTP POST）** ✅ |
